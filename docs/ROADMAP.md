# Roadmap — HearWrite 听写

功能想法登记处。状态：💡 idea（只有想法）→ 📋 spec（有设计）→ ✅ done。只记想法与规划；已实现功能见 README。

---

## 建议实施顺序

排序原则：**数据地基先行**（1→2→3 是一条依赖链，且 Room 还在 v1，现在改 schema 最便宜）；**便宜的体验修补随时插队**；**引擎 / 平台级改动单独成阶段**，不与迁移混做。

|#|条目|依据|
|---|---|---|
|1|错词本升级（错次 + 来源）|被 3、4、7 依赖；Room v1、迁移成本最低|
|2|听写统计（本地）|与 1 同代数据；`sessions` 表另起 v3，避免建空表|
|3|间隔复习队列|依赖 1 + 2|
|4|结束页重做本场 / 复习错词带原词行|本场数据已就绪，改动小、复习闭环收益直接|
|5|多选词库、抽 N 词听写|独立，纯 UI + domain；考前抽词是刚需|
|6|断点续播（来电 / 切后台 / 进程死亡）|唯一会丢进度的缺陷，但侵入引擎，单独阶段|
|7|拍手写答案自动批改|最大件；排在 1 之后，确认的错词才能带来源入库|
|8|播放节奏选项（遍数 + 倒序）|倒序几乎零成本；遍数才动引擎|
|9|反向默写模式|中；与 8 同属"朗读内容"维度|
|10|可打印听写练习纸 / 导出分享|独立；与候选池的分享图共用渲染层|
|11|每日计划与本地提醒（打卡）|依赖 2；需通知权限与 receiver|
|12|完善内置词库|长期数据工作，可随时穿插|

依赖链：**1 → 2 → 3**。4 部分依赖 1（跨场回查来源），5、6、8、9、10 相互独立，7 依赖 1，11 依赖 2。

> 验证环境：本机已有模拟器 `HearWrite37`（API 37 / x86_64 / google_apis，`~/.android/avd/`），迁移与进程死亡类验证走它；音频焦点、来电、TTS 音色等仍需真机。

## 1. 💡 错词本升级（错次 + 来源） 🤖

现状：`wrong_words` 只有 `word + addedAt`（`data/HearWriteDatabase.kt:13-17`），无来源、无错次；复习只能全量重听一遍，看不出哪些词反复错。Room `version = 1`，`exportSchema` 已开启且提交了 `app/schemas/…/1.json`，但全仓没有任何 `Migration` 基础设施。

**规划（spec 草稿）**：

- Room v2：`wrong_words` 增加 `errorCount: Int`（默认 0）、`lastWrongAt: Long`、`sourceLabel: String?`；`version` 升 2 + 手写 `Migration(1,2)` + 提交 `2.json`。
- 语义决定：`errorCount` **按场次计**（同一场内重复标记只 +1），`lastWrongAt` 取该场标记时间；`sourceLabel` 记内置词表 id（`default_<category>_<label>`）、历史行 id，或 null = 手动输入；来源失效（历史行被删）时降级显示"未知来源"，不删错词行。
- UI：错词本按错次降序、按来源分组；行内显示来源与错次；内置来源可跳回该词表预览。
- 落点：`WrongWordsRepository.add` 目前是纯 insert，需改 upsert 计数；`DictationViewModel` 标记错词时把来源传下来。
- 应用：高频错词优先排序，是"间隔复习队列"与"听写统计"的数据地基。

**验证**：模拟器 `HearWrite37` 上跑 instrumentation 迁移测试——建 v1 库写数据 → 升 v2 → 断言新列默认值与既有行完整；再真机走查排序/分组。仓库目前没有 `app/src/androidTest`，需同时补测试基础设施（见候选池「测试基础设施」）。

**决定**：不把"听写统计"的 `sessions` 表并进 v2——避免建一张暂时没有写入方的空表；统计另起 v3。

## 2. 💡 听写统计（本地） 🤖

现状：每场成绩只在内存里——`DictationViewModel` 的 `runStartedAtMs` / `_elapsedSec` / `runWrongCount` 随页面销毁即失，从不落库。

**规划（spec 草稿）**：

- Room v3：新表 `sessions`（`id`、`startedAt`、`sourceLabel`、`totalWords`、`wrongCount`、`durationSec`、`kind` = 正式听写 / 复习错词）；听写结束页写一条。
- UI：入口建议放首页「更多」菜单 → 统计页；先用列表 + 简单条形，**不引图表库**。
- 展示：趋势、错词率、高频错词、连续听写天数——聚合逻辑写成 `domain/` 纯函数 + 单测锁定。
- 纯本地，数据不出设备，与"错词本升级""间隔复习"共用同一份数据。

**依赖**：无。排在 1 之后只为每次只动一个迁移。

**验证**：聚合纯函数单测；真机连做两场听写后核对记录条数与错词率。

## 3. 💡 间隔复习队列（艾宾浩斯式调度） 🤖

现状：错词本 / 收藏 / 历史已具备，缺的是"哪一天该复习哪些词"的调度。

**规划（spec 草稿）**：

- domain：简化间隔调度（如 1/2/4/7/15 天…），纯函数 + 单元测试锁定；不引第三方 SRS 依赖。
- 入口："今日复习" = 到期词从错词本/收藏抽取，走现有 `prepareStartLines`，引擎零改动。
- **依赖：错词本升级（错次与时间戳）+ 听写统计（使用频率数据）**。
- 风险：本地单机、使用频率低时复习队列稀疏；排在 1、2 之后，避免空转。

## 4. 💡 结束页重做本场 / 复习错词带原词行 🤖

现状（修正）：结束页「复习错词」**已能**从本场 `lines` 回查富化行（`ui/DictationViewModel.kt:430-437`），并非纯裸词。真正的缺口是：① 没有「再听一遍」；② 跨场词与首页错词本入口仍退化成裸词（`ui/HomeScreen.kt:426` `wrongWords.map { it.word }`）；③ 跨场回查需要来源信息——依赖错词本升级的 `sourceLabel`。

**想法**：

- "再听一遍"：重放本场全部词，保留本次顺序与随机/起始设置。
- "复习错词"：携带本场原行（英文带 pos/释义，汉字带拼音/组词），而非裸词；跨场时按 `sourceLabel` 回查内置词表原行 / 载入历史文本，手动输入的词保持裸词。
- 落点：本场行数据在结束页直接可用，无需新表；`DictationSessionStore` 是一次性消费，重放所需的本场列表 ViewModel 内已持有。

## 5. 💡 多选词库、抽 N 词听写 🤖

**想法**：在词库中多选若干词表（可跨分类/教材），从中随机抽 X 个词听写。

现状：词库顶层有全库搜索（`ui/LibraryScreen.kt`），但分类页与词表预览页都没有筛选，也没有多选模式。

**规划（spec 草稿）**：

- 入口：词库浏览页多选词表（复用现有分类 → 词表列表结构 + Checkbox）。
- 交互：选 1+ 词表 → 显示合计词数 → 填抽词数 X（上限 = 总词数）→ 开始听写。
- 逻辑：跨表汇总条目 → 无放回随机抽 X 词 → 输出仍是标准词行。
- 落点：抽词在启动入口之前完成，结果继续走现有 `prepareStartLines` → `DictationSessionStore`；听写引擎、错词/历史/收藏机制均不动。
- 边界：X ≥ 总词数 = 全量随机；未选词表时按钮禁用。
- 待定：跨表重复词的去重策略；UI 入口位置。

## 6. 💡 断点续播（来电 / 切后台精确恢复） 🤖

现状：无生命周期与音频焦点处理（全仓无 `AudioFocusRequest` / `LifecycleEventEffect`）——切后台、来电时引擎照常推进，回前台常已跑过几个词；`pause()`/`resume()` 也只从当前词的 `speak1` 重放（`WordPhase` 是 `DictationEngine` 私有枚举，公开状态只有 `index`/`remainingMs`），停不到"第 17 个词的第 2 遍"。进程被杀则整场丢失：`DictationSessionStore` 是内存暂存且 `take()` 一次性消费，重启直接回首页。

**想法**：来电/切后台自动暂停，回前台从同一词同一遍继续；进程死亡后首页提供"继续上次听写（第 17/30 词）"。

**规划（spec 草稿）**：

- 中断源：注册 `AudioFocusRequest`（`LOSS_TRANSIENT` → pause，`GAIN` → resume，`LOSS` → 只 pause 不自动续）+ `LifecycleEventEffect(ON_STOP)` → pause；自动续播做成设置项。
- 精确到遍：`WordPhase` 提升为公开（或引擎暴露 `phase: StateFlow<WordPhase>`），加恢复入口 `start(lines, index, phase, remainingMs)`，从指定词的指定遍重启——恢复落点取"该遍重头"，不做遍内毫秒级续播。
- 进程死亡恢复：进行中会话（lines、index、phase、remainingMs、随机/起始设置、开始时间、runWrong 集合）落盘（DataStore 或 Room）；首页显示续播入口，超时（如 24h）或主动结束即清除。错词已即时入库，不随会话恢复。
- 复用：暂停/恢复沿用现有 gen 计数取消契约（不新增布尔标志）；倒计时 deadline 已是可重读的 `@Volatile`/StateFlow，恢复直接写回剩余 ms。
- 边界：来电中 `UtteranceProgressListener` 可能不回调 `onDone`，依赖现有 watchdog / `onStop(interrupted=true)` 兜底（`SystemSpeaker` 已有该分支）；续播不再 shuffle（顺序已在会话里）；进程死亡恢复只保证词序与词序号，不保证 TTS 缓存。
- 待定：遍内断点 vs 遍头重播（课堂口径后者更简单）；音频焦点用 `GAIN_TRANSIENT` 还是 `GAIN_TRANSIENT_MAY_DUCK`；后台自动暂停是否允许关闭。

**验证**：进程死亡恢复可在模拟器 `HearWrite37` 上用 `adb shell am kill org.yangtse.hearwrite` 复现/验收；音频焦点与真实来电必须真机。

## 7. 💡 拍手写答案自动批改（照片批改） 🤖

**想法**：听写结束后拍学生手写的答案纸，识别后与本次词表比对，自动逐词批改并给出成绩，错词并入错词本——把"标记错词"从手动自觉变成机器初判 + 人工确认。

**规划（spec 草稿）**：

- 入口：听写结束页成绩卡"拍照批改"；语言由本场词表判定（英文/汉字）。
- 复用：现有拍照识词整条管线——框选识别区域（`ui/OcrCropOverlay.kt`）→ 裁剪编码 → OpenAI 兼容视觉 OCR（同一 BYOK 提供方，无新网络出口）。
- 流程：识别行 → domain 比对归一化（大小写、中英全半角、空白、行序错位）→ 逐词对错 + 成绩 → 存疑项人工核对 → 确认的错词才并入错词本。
- **依赖：错词本升级**——确认后的错词要带 `errorCount`/来源入库，否则白批。
- 边界：识别为空/答非本场 → 提示重拍；识别结果永远不是最终判定，必须有人工确认缓冲；错词入库沿用现有 key（speakable headword）。
- 待定：批改成绩是否计入"听写统计"；行序错位/漏行的容忍策略；与 OCR 提示语"AI 识图可能存在误差"一致的口径。

## 8. 💡 播放节奏选项：朗读遍数与倒序 🤖

现状：英文固定 单词×2（可选跟读释义），汉字固定 生字→组词→生字；顺序只有"随机"，无倒序。

**想法**：

- 朗读遍数 1/2/3：英文与多字词语表生效；汉字单字"生字→组词→生字"是课堂范式，遍数选项对其默认不适用（待定是否放开关）。
- 倒序播放：与随机同级入口，`prepareStartLines`（`domain/StartLines.kt:10`）目前只有 shuffle 分支，倒序是加一个分支、**引擎零改动**。
- 遍数才需要动引擎：`WordPhase` 目前是 `DictationEngine` 私有枚举，需要先暴露/改造。

## 9. 💡 反向默写模式（读释义写单词） 🤖

**想法**：英文条目改为用中文语音朗读释义，学生听释义写英文词——汉译英默写训练，家长陪练常见场景。

**规划（spec 草稿）**：

- 引擎加 session-local mode：英文条目的朗读内容从单词本体换成中文释义（zh-CN 语音、走同一释义文本规则）；汉字模式不变。
- 界面：当前词显示从"隐藏英文"变为"隐藏释义/给出提示"的语义反转，文案与提示层需要区分。
- 错词/统计/结果页共用，不新增存储。
- 待定：模式入口位置（首页播放面板 or 词表预览启动台）；朗读内容 = 全部释义还是截取后的 speakable 释义。

## 10. 💡 可打印听写练习纸 / 导出分享 🤖

**想法**：任意标准词行源（草稿 / 词表 / 错词本）生成带序号、空白默写栏、答案区的听写练习纸，可打印或分享。

**规划（spec 草稿）**：

- 纯本地：Compose/排版渲染 → 系统打印（`androidx.print` 的 `PrintManager` + `PdfDocument`）或导出图片；无网络。仓库目前完全没有打印相关代码。
- 复用：现有"标准词行 → 条目"解析与补全（词性/释义）逻辑，保证答案栏与朗读内容一致。
- 待定：是否需要姓名/日期栏（课堂场景）；布局尺寸与分页。

## 11. 💡 每日计划与本地提醒（打卡） 🤖

**想法**：设定"每天 N 词"目标 + 本地通知提醒，配合统计形成连续打卡习惯。

**规划（spec 草稿）**：

- 纯本地：无账号、无后端；提醒用本地通知（闹钟式），不引推送。
- "今日任务"：从错词本/收藏/指定词表抽到期词，与"间隔复习队列"共用入口。
- 连续天数/完成率随"听写统计"展示；**依赖统计先行**。
- 现状缺口：未声明 `POST_NOTIFICATIONS`（API 33+ 需运行时申请）、无任何 `<receiver>`（重启后需重新排期）。
- 待定：提醒时间与每日词数的设置位置。

## 候选池（待评审，尚未排期） 🤖

以下为分析代码与同类应用后整理的候选想法，**尚未并入上方顺序**；评审通过后挪进正文。每条给出成本与我的建议。

### 数据与可靠性

- **用户词表长期保存（收藏不被 50 条上限淘汰）** — 现状：`HistoryRepository.add` 每次 `trimTo(MAX_HISTORY = 50)` 后 `pruneHistoryOrphans()`，收藏的用户词表一旦跌出前 50 条就被连带删除（`data/HistoryRepository.kt:63-72`）。家长反复用的同一份词表会无声消失。
  建议：**高**。最小改动是让被收藏的历史行免于裁剪；更彻底是新建"自建词表"表（可命名、可分类）。若采纳，可与错词本升级合并进同一次 v2 迁移（都是用户数据表的字段/结构变更）。
- **本地备份与恢复（导出/导入）** — 现状：`data_extraction_rules.xml` 主动排除 `datastore/` 与数据库，换机/恢复即丢全部用户数据；目前唯一的"导出"是把错词复制到剪贴板。无后端 = 本地导出是唯一的保命手段。
  建议：**高**。JSON 导出错词本/收藏/历史/设置（BYOK 密钥与 Keystore 绑定，换机解不开，**不导出**），走 SAF 文件选择器。
- **分享接收 / 文件导入** — 现状：只有一个 launcher activity，没有 `ACTION_SEND` / `ACTION_VIEW` 入口；从微信群、浏览器、笔记应用拿到词表只能手动复制粘贴。
  建议：**高**。成本低（intent-filter + 复用已有 `requestDraftImport` 一次性导入总线），收益直接。
- **测试基础设施（instrumentation 迁移测试 + Compose 冒烟 + CI lint）** — 现状：`app/src/androidTest` 不存在，CI 只跑 `assembleDebug + testDebugUnitTest`；v2/v3 迁移的正确性目前无法自动验证。
  建议：**高**，且应随错词本升级一起落地（迁移测试就是它的验收条件）。模拟器 `HearWrite37` 已就绪。

### 听写体验

- **看拼音写词 / 无声模式** — "看拼音写词语"是小学语文常见题型：不朗读，只显示拼音提示，学生写。现有提示层已按拼音渲染，成本主要在"跳过朗读"的引擎分支。
  建议：**高**（成本低、题型贴合）。
- **屏幕作答自动批改（键盘拼写 / 手写板）** — 不拍照、不出网：英文用键盘拼写、汉字用离线手写识别（如 ML Kit Digital Ink），即时判定。与"拍照批改"共享比对归一化 domain 层，且没有 OCR 误差与网络依赖。
  建议：**中高**。若两者只做一个，我倾向先做它而不是拍照批改。
- **提示层可配置**（拼音 / 释义 / 词性 / 全隐藏）— 现状提示层是固定组合。
  建议：**中**。与"看拼音写词""反向默写"共用一个提示层开关。
- **听写页屏幕常亮** — 听写中看屏幕，熄屏会打断节奏。
  建议：**中**（`FLAG_KEEP_SCREEN_ON` 级别的小改动，收益立竿见影）。
- **成绩单分享图** — 把结束页成绩卡渲染成图片分享（家长群打卡）。
  建议：**中**，与"可打印练习纸"共用 Compose → Bitmap/PDF 渲染层。

### 平台与打磨

- **冷启动与内存预算** — AGENTS.md 自记的"唯一真实弱点"：词典 3.3 MB → 约 15–25 MB 堆 + 数百 ms 解析，Phase 10 阈值是 500 ms；Android 17 又引入按设备 RAM 的内存上限。
  建议：**中高**。先测量（`am start -W` / Macrobenchmark），超阈值再把词典迁到 `Room.createFromAsset`，不要提前优化。
- **大屏 / 横屏 / 折叠屏适配** — 现状无任何 `WindowSizeClass`，全部单列固定布局；manifest 未锁方向（合规无风险），但平板/横屏观感差。
  建议：**中**。先保证旋转与分屏不崩，再考虑双栏。
- **快捷方式 / 桌面小组件** — 静态 shortcuts（开始听写 / 复习错词）成本低；Glance 小组件建议等"今日复习"落地后再做。
  建议：**中低**。
- **无障碍与大字号走查** — TalkBack 全流程 + 大字号走查；Android 17 新增 CJKV 输入的无障碍事件/TextAttribute API。
  建议：**中**。
- **应用内更新检查** — GitHub Releases 分发没有自动更新通道；可查 GitHub API 提示新版本。
  建议：**中低**。注意这会新增一个网络出口，需同步更新 AGENTS.md 的"四个出网点"清单。
- **动态取色（Material You）/ 预测性返回手势** — 都是打磨项，成本低。
  建议：**低**，可顺手做。
