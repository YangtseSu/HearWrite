# Repository Guidelines

## Project Overview

**HearWrite 听写** (package `org.yangtse.hearwrite`) — an Android dictation trainer for Chinese students: paste or photograph a word list → the app speaks each word with a countdown → the student writes it down → mark wrong words → review later. Two modes: **English** (英文) = word → (optional spoken Chinese meaning) → word, twice per word; **Chinese** (汉字) = 生字 → 组词 → 生字 (`"月" → "月，月亮的月"`), the classroom dictation call.

From-scratch Kotlin + Jetpack Compose. **[alice](https://github.com/vvenv/alice)** (third-party Expo/RN dictation app, MIT, author vvenv; the author's fork: github.com/YangtseSu/alice) is the **behavioral reference only** — nothing here reads or builds against it, and **this file is the sole behavioral contract**: not a port, predecessor behavior applies only where specified here.

**Non-goals:** iOS / Web / desktop; backend; the original's paid stack (Credits, Recharge, model tiers — **excluded entirely**); Expo/RN code reuse. Targets: `minSdk 33`, `targetSdk 37`, `compileSdk 37.2`. User-facing UI strings are hardcoded Chinese.

**Roadmap**: ideas and specs live in `docs/ROADMAP.md` — 💡 idea / 📋 spec / ✅ done, **unfinished items only**: a finished entry's body moves to `docs/implemented/` with its number untouched, so `Roadmap #N` references (here, KDoc, build script comments) keep resolving.

**`minSdk` policy**: a compile-time floor only — never constrain new dependencies or API usage to stay above it, never add `Build.VERSION.SDK_INT` guards or compat workarounds. A conflict (manifest merger, lint `NewApi`, compile/runtime failure) is fixed by **raising `minSdk`**, never by substituting an older function or dependency.

## Architecture & Data Flow

Single Gradle module `:app` until a real need appears; `domain/` stays Android-import-free.

- `ui/` — Compose screens (`HomeScreen`, `DictationScreen`, `SettingsScreen` + sub-pages, `LibraryScreen`/`LibraryListsScreen`/`LibraryPreviewScreen`/`LibraryDrawScreen`, `StatsScreen`, `OcrScanSheet`) and shared components (`CountdownRing`, sheet hosts in `HomeDrawers`, crop overlay, the 拍照批改 pane, `ListRows`), `theme/`. Material 3, light + dark, Chinese strings inline.
- `domain/` — pure Kotlin: word-list parsing (`WordRow`, `domain/Row.kt`), speech-text rules (组词朗读, 释义截取), the playback phase machine (`DictationEngine`), label ordering, 拍照批改 comparison (`AnswerGrading`). Unit-test target.
- `data/` — asset loader (built-in library), Room (wrong words / history / favorites), DataStore (settings + drafts), OkHttp clients (Youdao TTS, OpenAI-compatible TTS/OCR), system `TextToSpeech` wrapper, `DictationSessionStore` (session staging), `SoundEffects` (tick/chime WAV), `Haptics`.

State: `ViewModel` + `StateFlow` + `collectAsStateWithLifecycle`; **no DI framework** — Application-scoped singletons (`HearWriteApplication`) with lazy init. `navigation-compose`: Home / Dictation / Settings / Stats / Library (category → list → preview); Finish is a Dictation-screen end state and every dictation exit lands Home. Edge-to-edge (`enableEdgeToEdge()`): both bars stay transparent and their icons follow the **resolved 主题**, not the system uiMode (`MainActivity` re-syncs `WindowInsetsControllerCompat.isAppearanceLightStatusBars`/`…NavigationBars` from `darkTheme` on every theme change — `SystemBarStyle.auto` alone tints by system night mode). Word lists stage in `DictationSessionStore` as an in-memory handoff written just before navigating (process death restarts from Home). Only four outbound network call sites: Youdao TTS, Microsoft Edge Read-Aloud (WebSocket), optional OpenAI-compatible TTS, OpenAI-compatible vision OCR. **No backend.** File-by-file layout: `docs/DEVELOPMENT.md` §3.

### Built-in library (data assets in APK)

- `app/src/main/assets/` ships **verbatim** into the APK (standard AGP assets dir, no custom `sourceSets`/aapt wiring): `app/src/main/assets/<category>/<label>.txt`, `app/src/main/assets/dict/lexicon-en.json`, `…/dict/lexicon-hanzi.json`, `app/src/main/assets/compounds/compounds.json`, `app/src/main/assets/audio/tick.wav` + `…/audio/chime.wav`.
- **Never hand-edit a generated asset** — regenerate via `scripts/`. `python3 scripts/check-assets.py` validates the whole tree and runs in CI before Gradle; the data contract, the generators' inputs and the per-asset formats/体量 are in `docs/WORDLIST.md` (§5–§6, §9). **The word lists are themselves generator input**: a `字 | 拼音 | 组词` column feeds `lexicon-hanzi.json` (a 多音字 row flips that char's global default reading) and, for 人教版小学语文, `compounds.json`'s `learned` pool — write `字 | 拼音` unless the textbook prints a 组词 column.
- Categories = the 10 textbook dirs (`中考1600`, `高考3500`, `初中2182`, `人教版初中`, `人教版小学`, `人教版初中语文`, `人教版小学语文`, `外研版初中`, `闽教版小学`, `仁爱版初中`) + the public-corpus dir `义务教育语文课程标准` (the 2022 standard's 基本字表 300 + 常用字表 表一 2500 / 表二 1000, **one bare char per line**; the app fills 拼音/组词 from `dict/lexicon-hanzi.json`). Built-in entry id = `default_<category>_<label>`, `<label>` = filename sans `.txt`. **Labels are stable storage keys** — renaming orphans persisted history/favorite ids; never rename.
- Library-browser order (`compareLabels`, `domain/LabelOrder.kt`): category dirs, then labels within a category — grade rank 一→九, 上/下/全, Unit/Module number, 第X册; CJK runs compare pinyin syllable → stroke count → code point (the JDK `Collator` disagrees with ICU zh-Hans on 同音字, so it serves Latin runs only; no natural-compare fallback for CJK). The golden `library-label-order.json` fixture locks *order*; `LabelOrderCoverageTest` locks *coverage* — every CJK char in a shipped category/list name needs a `HANZI` entry, since a missing char falls back to code-point order invisibly (the fixture is regenerated with the same comparator).
- **Lexicon asset loading** (`data/LexiconRepository.kt`): `lexicon-en.json` (6.5 MB, ~53k entries) parses **lazily on first lookup** on `Dispatchers.IO` into a memory singleton; `lexicon-hanzi.json` and `compounds.json` likewise, **only when a row of that kind needs them** — a Chinese-only list (课标 字表, an OCR'd 生字表) never parses the English lexicon. **Never parse any of them on the startup path** (Application init / first frame); assets decode **from the stream into the domain types** (no JSON string, no DTO graph). Budget and fallback: if a measured cold start or peak crosses 500 ms / the heap, move the **dictionary alone** to a prebuilt SQLite (Room `createFromAsset`) and keep word lists as assets. Measurements and the 英文词典预热 path (`HearWriteApplication.warmEnglishLexicon()` — 前移到词库分类页，400 ms 延迟 + 进程内单飞，纯中文分类不触发): `docs/2026-09-18-DATA-MODEL.md` §4.
- **Row/lexicon split** (`docs/2026-09-18-DATA-MODEL.md`): a `.txt` row is **author data** — ordered, hand-editable, never rewritten by the app; the dictionary is a shared read-time lookup table composed by `LexiconRepository.resolve(rows)` into `ResolvedWord`, the row winning **field by field** (a 仁爱 row printing its own 词性/释义 still gains the textbook 音标 — what the old `enrichLines` could not give it). Routing is by `kind`: a **single Han char** reads `lexicon-hanzi.json` (拼音/组词), every other row `lexicon-en.json` (义项/音标) — a **multi-char Chinese word is never looked up in the English dictionary** and stays bare. `ResolvedWord` is the single runtime type for the dial, list rows, `AnswerGrading`, the engine and a staged session (the `displayRow()` flattener is gone); nothing is ever persisted back — drafts, history rows and staged sessions carry author data only. Display text comes from `domain/WordDisplay.kt`: the dial composes **美式音标 + 词性 into one hint line** (`/ˈæpəl/ n.` — a line of its own would cost the 204 dp disc a fourth row, §4.1), list rows and the 详情卡 label every accent **英 first** (`英 /let/ · 美 /let/ · v. · 让；允许`), and a missing accent omits its segment rather than printing a placeholder.

### Word-line format (behavioral contract)

One entry per non-empty line; `word | pos | meaning` (fullwidth `｜` accepted), 1–3 columns, a bare word alone valid, a trailing empty column dropped rather than written empty. Per kind: **English** `pos` = part of speech, `meaning` = 中文释义; **Chinese single char** (识字表/写字表) `pos` = tone-marked pinyin (`yuè`), `meaning` = 组词 containing the head char; **Chinese words** (词语表) bare, spoken as-is. Author-facing contract, examples and validation: `docs/WORDLIST.md` §3.

- `you're = you are` expansion: speak only the **left** side.
- POS normalization (ECDICT ↔ textbook spellings): `interj./exclam.→int.`, `na./un./pla./pn.→n.`, `vbl./pp.→v.`, `pref./suf./suff./comb./stuff.→abbr.`, `a.→adj.`, `pl.→n.`; strip a known POS prefix (`POS_PREFIX_RE` in `dictation.ts`) before treating column 1 as the headword.
- Row kind (`domain/WordKind.kt`, derived once at parse time from the **speakable** headword — `domain/Row.kt`'s `speak`, i.e. the left side of a `you're = you are` expansion): no 汉字 → `EN`; one 汉字 → `HANZI` (识字/写字表); longer → `WORD` (词语表). The two Chinese kinds switch TTS locale to `zh-CN` and hint rendering to pinyin-based. Every consumer reads `kind`, never a CJK regex on the raw line; the display text's `=` tail never decides, so `apple = 苹果` is `EN`.
- **音标 is not a row column** — pronunciation is dictionary data looked up at read time (`docs/2026-09-18-DATA-MODEL.md` §3.3); rows are never enriched in place.

### Speech-text rules

- **组词朗读** (`cjkWordSpeech`, single-char CJK only): speak `"组词的X"` — `月|yuè|月亮` → `"月亮的月"`; multi-char words/sentences return `""` (spoken as-is); function chars never compound (`的 地 得 着 了 吗 呢 吧 啊 呀 啦 嘛 么` — `NO_COMPOUND_HEADS`). Candidates come from three tiers (the entry's own 组词 column → the learned pool → the common pool), pinyin-filtered by `syllableMatches`; a pinyin-less row infers the reading from its most frequent common-pool word. ⚠️ **Never dedupe candidates by word — walk the raw array and take the first filter pass** (dedupe kills polyphone readings). Tiers, filter, the `朝|zhāo` / `澄|dèng` walk-throughs: `docs/TTS.md` §5.
- **朗读释义** (`speakableMeaning`, English entries): strip a leading POS prefix, take the first non-empty sense, cut at visual width 12 — details in `docs/TTS.md` §5. Empty result = nothing to speak.
- **No pinyin library** (`pinyin4j`/`TinyPinyin`/…): textbook rows carry pinyin, compound data carries per-word syllables, and the parser never generates pinyin.

### Playback engine (`DictationEngine`)

Coroutine state machine on its own `SupervisorJob` scope; per word: `speak1` → 700 ms gap → `speakMeaning` → `speak2` → `interval` countdown → next word. `speakMeaning`: CJK **single char** → `cjkWordSpeech` output, **always** (the classroom call — the 朗读释义 toggle only gates English glosses); multi-char CJK → nothing (word spoken as-is, twice); English → `speakableMeaning`, only when 朗读释义 is on. Settings: interval 1–10 s (default 7, step 0.5), auto-next on/off, speech rate. Pause/resume; leaving the screen stops playback.

Start options are session-local (not persisted), offered by Home's playback panel and the `LibraryPreviewScreen` launchpad: **随机顺序** (Fisher–Yates over a copy of the parsed list; not switchable mid-dictation) and **起始序号** (Home picks it from the display-state word list; clamped when the list shrinks). Both funnel `prepareStartRows` (`domain/StartLines.kt`) — slice from `startIndex`, then shuffle — and stage resolved rows in `DictationSessionStore` before navigating; the engine plays the list it is given and knows neither option. A third launchpad, **多选词表 → 抽词听写** (`LibraryDrawScreen` over the process-scoped `LibrarySelectionStore`; rows ticked in `LibraryScreen`/`LibraryListsScreen`), assembles a pool first: the member lists' lines in selection order, deduped by **speakable headword** (`domain/DrawWords.kt` `dedupeByHeadword` — the 错词本 key, first occurrence keeps its columns), enriched like the preview, then drawn without replacement (`sampleWords` = shuffle + take; X ≥ pool = full random). Drawn lines stage like any run and carry the `multi:<id>,<id>,…` provenance label (`domain/SourceLabel.kt`) so their wrong marks resolve back to the member lists; the engine is untouched.

Implementation constraints (each fixed a real RN-predecessor bug — never regress):
- Cancel via `Job.cancel()` + a **generation counter** bumped on every start/pause/stop/skip/prev, re-checked after every suspension. Never boolean flags.
- Cross-thread playback fields are `@Volatile` (`TtsChainSpeaker.activeClip`/`interrupted` — `stop()` runs on any thread that cancels playback: Main engine calls, MediaPlayer callback threads).
- The countdown deadline lives in a `StateFlow`/`@Volatile` field **re-read every tick**, so live interval changes apply mid-countdown (a predecessor captured it once and interval changes silently did nothing).
- `speak1` failure → **no retry**: skip the gap, advance to the next phase (`speak2` is the natural second attempt); retry loops froze the app.
- Auto-next off: after `speak2` clear the scheduler but keep the session alive; re-enabling resumes from the current word at the `interval` phase.
- End of list → completion state + chime; system back during dictation asks for confirmation, never exits silently.

UI: countdown ring (last-second tick, `clearAndSetSemantics` announcing remaining seconds); current word **hidden by default** — tap to reveal, the core interaction; a `/音标/ 词性` hint line over the 释义/组词 (展开全部 opens the 详情卡 for a word or gloss the disc cannot hold); 标记错词 (warning haptic, `Haptics.notifyWarning`); prev/pause/next/stop; progress `n / total`. The whole session holds `View.keepScreenOn` (set while `DictationScreen` is composed, cleared on exit) — active, paused or finish card, a multi-minute run never hits the screen timeout or the lock screen.

### TTS priority chain

Order: **Youdao** (default) → **微软 Edge** (keyless) → optional **OpenAI-compatible BYOK**, with **system TTS as the sole fallback**, always available. `Speaker` contract: `suspend fun speak(text, lang): Boolean` + `stop()` — `false` on failure, never throws into the caller. The three network sources are **peers**: the active source plays only its own cached clips (a leftover Youdao clip must not surface under Edge/custom), and any failure falls through to the system voice, so dictation never blocks on a download or an outage. A cold-start cache miss waits a bounded ≈4 s (joining that source's own single-flight prefetch) before falling back, so one dictation keeps one voice; the wait is cancellable. Prefetch runs in the background for the current word, the next word and the current line's meaning pass (English gloss; 组词 phrase under EDGE/CUSTOM). The 组词 phrase (`"月亮的月"`) follows the same routing **except** under Youdao, whose dict voice cannot serve a sentence: there it goes straight to system zh-CN TTS with **no network attempt** and is never prefetched.

Per-source protocol, voice selection, cache keys and failure handling — Youdao's endpoint/params/256-byte floor, the vendored Edge client and its maintenance ritual (incl. LGPLv3 provenance), system-TTS init/`onDone`+`onError`/watchdog rules and voice-name helpers, and the two BYOK wire shapes — live in `docs/TTS.md`. Preset lists are code-owned single sources of truth: `data/TtsProviderConfig.kt` and `data/OcrProviderConfig.kt`, both pinned by unit tests.

### OCR import (拍照识词)

Photo Picker or camera capture, **always through the 选定识别区域 crop step first** (`ui/OcrCropOverlay.kt` — Android guarantees no system crop, so HearWrite ships a Compose overlay), then encode (longest edge ≤ 1600 px, JPEG ≈ 0.82, base64 data URL) and `POST {base}/chat/completions`. The reply goes through the language-specific extractor (`OcrService.extractOcrLines`) before parsing: English mode keeps ASCII word lines only (音标/Chinese never become entries; mixed rows yield their leading headword); Chinese mode keeps 汉字 runs only (pinyin/latin/digits dropped, 生字/词语表 headers skipped). Prompts are **verbatim** Chinese strings in `OcrService.kt` (language picked in the scan sheet), pinned by unit tests. BYOK only — the user's own key, no built-in key, no credits, no quota. Show the disclaimer `"AI 识图可能存在误差，请核对识别结果"` at OCR entry points; errors surface as Chinese messages with a retry.

Crop constants and bitmap lifecycle, the extractor rules, the preset table (`data/OcrProviderConfig.kt`, default Zhipu `glm-4v-flash`) and the dropped predecessor presets: `docs/OCR.md` §1.

### 拍照批改 (photo grading, Roadmap #11)

The same BYOK vision provider — no fifth outbound endpoint — reads a **student's answer sheet** and judges it against the run that just finished. Entry: the finish card's 拍照批改 button → the pane replaces the score card → camera/album → 选定识别区域 → `OcrService.recognizeAnswers`. Language is **the run's own** (`domain/isCjkRun`: a strict majority of speakable headwords are Chinese), never a picker.

- **Prompts are the inverse of the word-list ones** (`ENGLISH_ANSWER_PROMPT` / `CHINESE_ANSWER_PROMPT`): transcribe the student's **own writing**, 拼写错误 included — 不要自动纠正 — plus the 题号, skipping blank lines. A silently corrected spelling would grade correct and lose the mistake; a dropped 题号 would shift every answer after a skipped word. `extractAnswerLines` therefore keeps every fenced-stripped line verbatim (no headword salvage, no language filter — unlike `extractOcrLines`).
- **`domain/AnswerGrading.kt`** is the pure judgement (Android-free, unit-tested): normalization + expected/answer key sets, 题号-first placement, Needleman–Wunsch alignment of the leftovers, then an out-of-order recovery pass; verdicts 正确 / 错词 / 漏答 / 多余作答 with `doubt` on near misses, blanks and stray lines (`GradeResult.mismatched` warns when the paper barely overlaps this run). Algorithm detail: `docs/OCR.md` §2.
- **Nothing reaches the 错词本 without confirmation** (`DictationViewModel.confirmGrade`, the only photo→book path): the pane lists every judged line with what was written, ticks default to 错词+漏答, and the ticks the human leaves are written per head once with the run's `sourceLabel` (a 复习错词 round writes nothing, like a manual mark). The score card, 错词本 chips, 复习错词 and 听写统计 all follow the same book, so a graded run behaves exactly like a hand-marked one.

### Persistence

- **Room**: `wrong_words` (word, addedAt, errorCount, lastWrongAt, sourceLabel — the speakable-headword key; `errorCount` counts dictation **runs**, not presses), `history` (user lists only — id, text, createdAt; **cap 50**, drop oldest, favorited rows exempt; `text` is the authored list — the looked-up `enrichedText` column was dropped in v5), `favorites` (entry ids: `default_*` or history ids), `sessions` (Roadmap #3 听写统计: one row per **completed** run — startedAt, sourceLabel, totalWords, wrongCount, durationSec, kind `dictation`/`review`; stopped/abandoned runs record nothing). Wrong words and favorites are keyed by the speakable headword / entry id. A wrong mark's / session's `sourceLabel` is one such id or a 抽词听写 pool's `multi:` label — the resolver looks the word up in every member list and the UI titles the group `首个可解析词表 等 N 个词表` (or 多词表 when they are gone); a source that no longer resolves degrades to 未知来源/a bare headword, never drops the row. Aggregation is pure (`domain/Stats.kt` — `summarize`/`dailyStats`/`streakDays`, zone + today injected), rendered by `ui/StatsScreen.kt` with no chart library, reached from 首页 更多 → 听写统计 and the finish card's own 听写统计 button (the card just wrote the run's row; Home's header has no room for a fourth icon, so the depth is cut at the finish card instead). **Schema is exported** (`exportSchema = true`, ksp `room.schemaLocation` → `app/schemas/`) and the JSON is committed — bump `version` + add a migration whenever entities change; never change entities silently.
- **DataStore Preferences**: word-input draft (debounced 500 ms; the library preview's 载入草稿 feeds it via a one-shot import bus, `HearWriteApplication.requestDraftImport`), speech rate, interval sec, auto-next, read-translation, sound effects, TTS source (`youdao|edge|system|custom`), one provider config JSON per preset (map keyed by preset id; legacy single-blob keys migrate away on write) for TTS and OCR alike, theme (light/dark/system), 动态取色 (Material You `dynamic_color`, **off by default** — on, `HearWriteTheme` swaps the curated 纸质/墨色 scheme for `dynamicLight/DarkColorScheme()`, while `hearWriteSemantics`' 朱砂/收藏金/成功 accents stay curated: they are pinned to contrast rules a wallpaper cannot promise). **BYOK API keys are sealed at rest** before the config maps are written — AES-256-GCM via the Android Keystore (`data/KeystoreCipher.kt`, shape `v1.<iv-b64>.<ct-b64>`); key generation requests a **StrongBox** key first and retries without it on `StrongBoxUnavailableException` at `generateKey()`. Only a total keystore failure degrades to plaintext, and the save flow then reports it to the UI (`ttsKeySealed`/`ocrKeySealed` → one-shot hub toast), never a silent plaintext save. Legacy plaintext keys (pre-0.3.2) are read through and sealed on the next save; an undecryptable sealed value (keystore wiped on restore/transfer) resolves to `""` so the user re-enters the key rather than the app sending garbage. `data_extraction_rules.xml` excludes `datastore/` and the database from backup and device transfer — sealed keys never leave the device. Mechanics: `docs/DEVELOPMENT.md` §6.
- Built-in library content is **never** persisted — read from assets each launch (cached in memory).

### Ported pitfalls (each fixed a real bug in the RN predecessor — write them correctly from day one)

- **Debounce flush**: the word-input draft persists debounced (500 ms) — flush pending input in `DisposableEffect.onDispose`; the predecessor cleared the timer without flushing and lost the last keystrokes on exit.
- **Re-entry guards before the first suspension**: claim via `Mutex.tryLock()` (or a `@Volatile` flag) **before** the first await; a check after a suspension point lets double-taps through (the predecessor double-charged OCR).
- **Every `launch` catches**: async blocks `try/catch` and surface failures in the UI; a swallowed error made a failed request look successful.
- **List keys**: stable ids or indices — never content that changes while editing (remounts inputs mid-typing).
- **Sliders**: native Compose `Slider` only (TalkBack increment/decrement comes free), each with a Chinese `contentDescription` ("听写间隔秒数" etc.) — a bare "滑块" is useless. Never hand-roll Canvas sliders. Icon buttons carry `contentDescription`.
- **Threading**: DB/file/network off the main thread (`Dispatchers.IO`); no `Thread.sleep`/`Handler.postDelayed`/`Timer` for playback timing — coroutines + `delay()`.
- No `LiveData`, no `SharedPreferences`, no XML layouts, no `GlobalScope`; business state in `StateFlow` (`mutableStateOf` only for ephemeral UI state like text-field values).

## Repo hygiene (non-negotiable)

- **Never push without explicit permission.** No `git push` of any form — plain, `--force-with-lease`, branch rewrite, tag or branch deletion — unless the user asked for it in that same turn. Committing is local work; publishing is the user's call. When a commit is ready to publish, say so and wait for the go-ahead.
- **No hardware identifiers in tracked content.** Docs, code comments, commit messages, test fixtures and file names MUST NOT carry a device model, serial or other device-unique id, or an emulator/AVD name. Name the class instead — `真机` / `模拟器` / `device` — keeping only what the evidence needs (API level, locale, screen size, app version). A ROM/vendor name is allowed only where that ROM *is* the finding; never shorthand for "the machine I ran this on". The signing certificate's subject identity is out too — see `docs/DEVELOPMENT.md` §4.4.

## Code Conventions

- **Language**: identifiers, comments, KDoc and commit messages in **English**; user-facing UI strings and spoken sample text hardcoded **Chinese** inline — no `strings.xml`, no i18n.
- **Style**: official Kotlin conventions (4-space indent, LF, UTF-8); `ktlint`/`detekt` not configured — do not add tooling mid-phase without noting it in the commit message. No `!!`; `require`/`check` for programmer errors, defensive catch-to-fallback only at network/audio boundaries.
- **Naming**: `*Screen.kt` composables, `*ViewModel.kt`, `*Repository.kt`, `*Dao.kt`; `domain/` pure functions are top-level and testable.
- **Errors**: user-facing failures become Chinese strings; network/audio layers never throw into UI — they degrade (TTS chain, OCR retry).
- **UI conventions** (distilled from the 2026-09 UI audit, `4c40ab7`; full findings archived in `docs/implemented/2026-09-12-UI-AUDIT.md`):
  - **Use the shared components — never hand-roll a second version**: `ui/theme/Type.kt` (all 12 type styles; `Typography.wordHead` = row headword), `ui/Format.kt` (the only formatter: `formatInterval`/`formatDuration`/`formatDay`/`formatStamp`/`formatPercent`), `ui/Feedback.kt` (the one-shot message channel — `MessageHostScope`, because sheets/dialogs are separate windows where a screen-level `SnackbarHost` is invisible), `ui/ListRows.kt` (`RowToggle(checked, role, onToggle)` — whole row is the control, indicator purely visual), `ui/SettingsProviderForms.kt`.
  - **One-shot confirmations go through the message host, never `Toast`** (15 inline `Toast.makeText` once; zero now). Destructive actions get a confirmation dialog and a destructive-styled button (`error` foreground), not just a label.
  - **Toggle rows**: the row itself is `toggleable`/`selectable` (one focus stop); the inner `Switch`/`Checkbox`/`RadioButton` is `onCheckedChange = null`. Never put `contentDescription` on a value `Text` — it replaces the text TalkBack needs.
  - **Terminology**: one name per thing per screen. `API Key` / `Base URL` / protocol names stay in English (users align them with provider consoles); `OCR` is code-speak — the UI says `识别服务`.
  - **Semantic colors are paired and constrained**: `cjkAccent`/`cjkContainer`/`onCjkContainer` carry the 汉字 identity (never for English/POS content — `Color.kt` hard rule); `successContainer`+`onSuccessContainer` pair like `errorContainer`. Values were measured for contrast ≥ 4.5:1 and ΔE₀₀ ≥ 10 from error red — do not retune casually.
  - **Insets**: every full-screen `Scaffold` bottom bar gets `.navigationBarsPadding().imePadding()` (baseline: `LibrarySelectionBar.kt:35-40`); `SettingsSubPage`'s scroll column needs IME too. The manifest sets `android:windowSoftInputMode="adjustResize"` (`617bc55`), but IME space is still per-screen (`imePadding()` per screen; `windowSoftInputMode` is never a substitute).
  - **Navigation**: all route pushes go through `HearWriteApp.openTop` (`launchSingleTop`; prevents double-tap stack growth on top-level and parameterised routes).
  - **State**: ephemeral dialog/sheet state uses `rememberSaveable` (rotation); one-shot async failures surface in the UI; irreversible clears get a counted confirmation; single-row deletes offer a Snackbar 撤销.
- **Commit discipline**: one thing per commit (`feat:` `fix:` `docs:` `data:` `chore:`); **every commit must compile**; verification evidence (device demo, measurements) in the body. Before tagging a release, append a user-facing Chinese section to `CHANGELOG.md` (`## [x.y.z]` matching the tag) — the release workflow builds the GitHub Release body from it and fails without it.

### AI attribution emoji (vibe commits)

Primarily AI-generated changes append ` 🤖` (leading space, last word) to the **commit subject line** — `fix: correct Edge voice clip cache key on voice switch 🤖`.

- Human-authored commits carry none; mixed commits (the normal agent-driven case) count as AI-generated. Subject only, body plain; conventional-commit prefixes unchanged, the emoji trailing them.
- No model name in it — the suffix marks AI work generically, and the release workflow / CHANGELOG parse plain subjects.
- **Roadmap entries**: an entry in `docs/ROADMAP.md` added/edited by an AI agent carries ` 🤖` at the end of its heading (e.g. `## 💡 间隔复习队列 🤖`), same convention, so human-authored entries stay distinguishable. Decorative for humans only — no workflow parses it.

## Testing & QA

- Unit tests (JUnit4 + `kotlinx-coroutines-test`) are the `domain/` behavioral-contract gate; `app/src/test/` names the pinned contracts — line parsing and POS normalization, kind derivation, `cjkWordSpeech` (tier order, learned-first, polyphones), `speakableMeaning`, `compareLabels` (+ `LabelOrderCoverageTest`), `DictationEngine` (fake `Speaker`, `runTest` virtual time: phase order, no retry on `speak1` failure, no stray speaks after cancel, auto-next hold, generation races, live interval change via `advanceTimeBy`), `Stats.kt`, `AnswerGrading.kt`, `StartLines.kt`, `ResolvedWord.kt`/`WordDisplay.kt`, and the `data/` pure logic (Youdao URL/cache forms, provider-config codecs and wire bodies, OCR extractors/fence stripping/answer-sheet extraction, session-record clamping, `DictationSessionStore`'s take-once handoff). Do not delete coverage of these contracts; new behavior follows the same pattern.
- **Testing stack decisions** (2026-09 audit): **no DI framework, no mocking library, no Robolectric** — Android-touching classes expose a narrow seam (interface or lambda field) with hand-written fakes (`SecretCipher` → `ProviderConfigSealTest`, fake `Speaker` → `DictationEngineTest`); new tests follow that pattern instead of adding MockK/Hilt. Business logic stays in Android-free `domain/`/`data/` pure functions so the JVM suite (no device) is the gate; no Compose UI tests, no screenshot tests, no Jacoco — the UI is `StateFlow` glue pinned one layer down. Keep it that way unless a concrete need appears.
- Assets/dict data are **read-only fixtures** — tests may load from `app/src/main/assets/`, never modify it. `DataFixtureTest` locks the textbook shapes and the 课标字表 (exact 300/2500/1000 counts, one bare char per line, 表一 ∩ 表二 = ∅, 基本字表 ⊆ 常用字表); `LexiconRepositoryTest` drives lookup/composition through the asset-reader seam and locks the routing rule (bare English → `lexicon-en`, bare single Han char → `lexicon-hanzi`, multi-char Chinese → no lookup), the field-by-field fallback and the shipped-asset 仁爱 / ipa-dict / missing-both cases. `python3 scripts/check-assets.py` is the CI data gate (before Gradle).
- `app/src/androidTest` (Room): real-SQLite migration tests (`MigrationTestHelper` — v1→v2 wrong words, v2→v3 sessions, v3→v4 label rename, v4→v5 drops the history lookup column, each diffing the migrated schema against the committed JSON) plus DAO behavior JVM fakes cannot reach (recordMark upsert counts, favorited-history cap exemption). Every new migration MUST get one; `connectedDebugAndroidTest` runs them on CI's API 33 emulator — the `minSdk` floor and thus the oldest framework SQLite (3.32) the app can meet, because a migration must be proven on that floor: `MIGRATION_4_5`'s former `ALTER TABLE … DROP COLUMN` needs SQLite 3.35 (API 34) and failed outright on Android 13 while the suite stayed green on 36.
- Verification workflow: `assembleDebug` + `testDebugUnitTest` green → install → exercise the changed surface on device → commit (demo result in the message).
